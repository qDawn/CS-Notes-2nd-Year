
## Worst - Case Analysis 

Worst case running time, largest possible running time given size n (Captures efficiency in practice)

Average case running time, obtained from running time on a random input as a function of size n

# Polynomial-Time

Brute force. typically takes 2^n time or worse for inputs of size n


Desirable scaling property: When input size doubles the algorithms should only slow down by a constant factor C 

if that condition is met it is poly-time

## Worst-Case Polynomial-Time
- an algorithm is efficient if its running time is polynomial
- Although n^20 is technically poly-time, it would be useless in practice
- Avoid the exponential cost of brute force
